# 手帐工作室界面优化设计

## 1. 背景

当前前端已经具备登录、创建、生成进度、历史列表、素材库和手帐预览导出能力。界面风格已有温柔拼贴倾向，但外层应用 UI 仍存在以下问题：

- 全局配色变量含义混乱，粉、蓝、米色同时承担主色、辅助色和状态色。
- 顶部导航和详情页按钮使用较强玻璃高光，和手帐纸张气质不完全一致。
- 创建页、历史页、素材库都使用通用卡片结构，缺少“创作台面”的产品识别度。
- 上传、筛选、历史卡片和素材卡片的 hover、active、focus 状态不够统一。
- 手帐画布已经有照片和纸张质感，但外层容器抢焦点或显得像普通后台页面。

本次优化目标是把已登录后的应用界面统一成“手帐工作室”：外层 UI 像一张安静的创作台面，使用纸张、照片、标签、胶带和温暖材质建立识别度，同时保留现有功能和数据流。

## 2. 设计目标

- 保留现有 React、Vite、Tailwind v4 和自定义 CSS 结构，不引入新 UI 框架。
- 不改动后端 API、路由结构、手帐 JSON、画布渲染和 PNG 导出逻辑。
- 统一全局视觉变量，让页面、按钮、卡片、状态色使用同一套语义色。
- 强化创建页作为核心入口的层次：照片上传台、记录纸、心情标签和生成按钮。
- 历史页和素材库从通用网格升级为更有手帐感的纸页、素材抽屉和标签筛选。
- 预览页保留画布主角地位，外层工具栏更安静，减少高光玻璃按钮。
- 完整覆盖 hover、active、disabled 和 focus-visible 状态。

## 3. 视觉语言

### 3.1 色彩

采用温暖纸张系，而不是当前粉蓝并列的高饱和组合：

| 语义 | 建议值 | 用途 |
| --- | --- | --- |
| `--color-background` | `#f5efe5` | 全局台面背景 |
| `--color-paper` | `#fffaf2` | 表单、卡片、导航底面 |
| `--color-paper-strong` | `#fffdf8` | 输入框、画布托盘、重点卡片 |
| `--color-ink` | `#332319` | 标题和主文本 |
| `--color-paragraph` | `#6f5645` | 正文和辅助说明 |
| `--color-border` | `#dcc7b6` | 纸张边线 |
| `--color-accent` | `#b86f5b` | 主按钮、选中态、错误提示 |
| `--color-secondary` | `#b9c8a9` | 轻辅助状态和标签 |

粉色不再作为默认主色，蓝色不再作为大面积辅助色。状态文案仍需清晰，错误提示使用陶土色加深，不使用过亮粉色。

### 3.2 材质

- 全局背景使用非常轻的纸纹、斜向光感或重复线纹，避免纯平背景。
- 卡片更像纸页：低阴影、浅边框、轻微内高光，不使用厚重通用投影。
- 上传后的照片缩略图保留白边和轻微旋转，让“照片放在桌面上”的感觉进入创建页。
- 标签、筛选项、心情选项使用短矩形纸签，不默认全 pill。
- 圆角统一为 8-12px；按钮 8px，卡片 10-12px，照片 6-8px。

### 3.3 字体

- 保留当前手帐画布内的 `Bailu Qiaoli` 手写字体。
- 应用外层继续使用系统 sans 字体，不新增外部字体依赖。
- 标题提升字重和字号，正文控制行宽，标签使用中等字重，不再依赖全大写英文风格。

## 4. 页面方案

### 4.1 应用壳与导航

- `App.tsx` 路由结构不变。
- `top-nav` 从高光玻璃胶囊改为固定宽度的纸质工具条。
- 品牌区保留 `Komorebi`，视觉上像贴在台面上的标签。
- 活跃导航项使用陶土色背景或底边标记，非活跃项保持纸色 hover。
- 移动端继续隐藏 nav label，只显示图标。

### 4.2 创建页

创建页是本次优化重点。

- 外层布局仍为两列，左侧图片上传，右侧描述表单；移动端折叠为一列。
- 左侧 `create-panel` 改为“照片上传台”：上传区域使用虚线纸框、轻纹理背景，上传提示更像操作区标题。
- 已上传图片保留 1:1 缩略图，但增加白边、轻微旋转、纸质阴影和拖拽目标反馈。
- 右侧表单改为“记录纸”：文本域、日期、地点、心情选择共享统一输入样式。
- 心情选择面板改为纸签网格，选中项使用陶土色或鼠尾草绿，不使用高饱和粉蓝。
- 提交按钮为核心动作，使用陶土色填充，hover 时轻微上移，active 时回落。

### 4.3 历史页

- 空状态保留创建入口，但表现为一张空白纸页和简洁说明。
- 有数据时，历史卡片像保存的手帐纸页：缩略图带照片白边，正文摘要限制行数，元信息以纸签呈现。
- 卡片 hover 只做轻微位移和阴影变化，避免大幅动画。
- 保留现有缩略图加载、URL 回收和路由跳转逻辑。

### 4.4 素材库

- 保留筛选维度：分类、状态、标签。
- 顶部统计改为素材抽屉式摘要：approved、draft、rejected 使用同一色系的不同明度，不再使用粉蓝强对比。
- 筛选区从普通边框卡片改为标签条区域，选中按钮使用主色，未选中按钮使用纸色。
- `AssetCard` 保留管理状态切换逻辑，视觉上减少通用卡片感，让素材预览区域像放在纸面上。

### 4.5 预览页

- 不改 `JournalCanvas` 渲染、缩放、图片加载、lightbox 和 `html-to-image` 导出逻辑。
- 详情工具栏从玻璃按钮改为纸质工具条，导出按钮仍为清晰主操作。
- 预览面板改为桌面托盘效果：背景安静、阴影更低，避免和画布内容竞争。
- 加载和错误提示保留当前位置，但使用统一颜色和字重。

### 4.6 登录页

- 登录页属于未登录入口，保持现有结构。
- 将高饱和粉蓝渐变降为同一纸张色系，避免和已登录应用断裂。
- 输入框、提交按钮和错误提示同步使用全局变量。

## 5. 组件与代码边界

本次实现主要修改：

- `frontend/src/styles/globals.css`
- `frontend/src/components/ui/button.tsx`
- `frontend/src/components/ui/card.tsx`
- `frontend/src/components/AssetCard.tsx`
- 必要时小幅调整页面 className 或文案层级：
  - `CreateJournalPage.tsx`
  - `JournalHistoryPage.tsx`
  - `AssetLibraryPage.tsx`
  - `JournalDetailPage.tsx`

不修改：

- 后端 API。
- 认证和 token 逻辑。
- 图片上传、拖拽排序、生成任务和历史查询数据流。
- `JournalCanvas` 的版式渲染、导出尺寸和导出逻辑。
- 素材状态更新行为。

## 6. 状态要求

所有可交互元素需要具备：

- hover：背景、边框或阴影变化。
- active：轻微下压或阴影收回。
- disabled：降低透明度并阻止 pointer 交互。
- focus-visible：清晰可见的外圈，不只依赖颜色。

页面状态保留现有行为：

- 创建页图片为空时显示错误。
- 描述为空时显示表单错误。
- 历史页加载、错误、空状态。
- 素材库加载、错误、筛选为空状态。
- 预览页加载、错误、图片加载中、导出错误。

## 7. 响应式要求

- `top-nav` 在 520px 以下保持图标导航。
- 创建页在 860px 以下单列排列。
- 素材库卡片继续使用现有 `sm / lg / xl` 网格。
- 预览页画布缩放逻辑不变，外层容器不能引入横向溢出。
- 所有按钮文本在移动端不能溢出容器。

## 8. 验收标准

- 已登录后的创建、历史、素材、账号、预览页面视觉语言统一。
- 创建页一眼能看出是手帐创作工具，而不是普通表单后台。
- 手帐画布在预览页仍是视觉焦点，外层工具栏不抢焦点。
- 按钮、输入框、卡片、筛选项和心情选项状态一致。
- 历史页空状态和有数据状态都可用。
- 素材库管理状态切换入口仍可键盘访问。
- PNG 导出行为保持不变。
- `npm run build` 通过。

## 9. 非目标

- 不新增主题切换。
- 不新增动画库。
- 不更换图标库。
- 不改手帐画布内部版式。
- 不改 API 或数据库。
- 不新增功能页面。
