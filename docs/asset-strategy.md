# 素材库策略

## 1. 目标

第一版需要一个免费、可控、高质量的内置素材库，用于生成温柔拼贴风格手帐。素材库应优先保证风格统一、授权清晰和可人工检查，不追求数量。

素材库需要能在网站内预览，方便人工检查质量、标签、授权和使用效果。

## 2. 素材来源

素材来源优先级：

1. 使用 Rough.js 和项目内模板生成的 SVG 素材，统一手绘质感和颜色体系。
2. 项目自绘 SVG 素材。
3. 免费且授权宽松的外部 SVG 素材，必须人工审核后再进入素材库。
4. AI 生成的自有素材，作为后续扩展，不作为第一阶段硬依赖。

第一版优先使用 Rough.js 生成基础素材，避免授权风险和风格不统一。生成后的 SVG 文件随项目版本管理，进入预览页检查；生成脚本只作为维护素材库的工具，不在用户生成手帐时临时生成未知素材。

可自绘的素材类型：

- 胶带：纯色、条纹、格纹、半透明纸胶带。
- 纸张：便签、撕边纸、标签、圆角卡片。
- 手绘元素：星星、爱心、花、小太阳、云朵、箭头、波浪线。
- 场景贴纸：旅行、咖啡、天气、生日、节日、散步、宠物。
- 装饰纹理：点点、网格、虚线、划线、高光笔。

外部素材只作为补充。引入外部素材前，需要记录来源和 license，不使用授权不清晰、质量不可控或需要复杂署名义务的素材。项目虽然不涉及商业用途，但第一版默认仍优先选择 CC0、MIT、Apache、ISC 或明确允许再分发的素材；需要 NC、SA 或强署名要求的素材只能先进入 draft，并在预览页标清授权后人工决定是否保留。

lucide-react 只用于网站 UI 图标，例如按钮、导航和工具栏；不作为手帐装饰素材。普通 UI 图标直接放进手帐会削弱温柔拼贴风格。

## 3. 质量标准

进入素材库的素材必须满足以下标准：

- 风格符合温柔拼贴，不使用明显卡通化、商务化或通用图标感过强的素材。
- 视觉上适合放在手帐页中，不能像普通 UI icon。
- SVG 结构干净，尺寸可缩放，边界框合理。
- 颜色柔和，能融入温暖、生活化的手帐风格。
- 单个素材有明确用途，不加入意义模糊或低质量填充素材。
- 同一分类下素材风格一致。
- 素材文件命名清晰。
- 每个素材都有标签和授权信息。
- 外部素材必须有可追溯来源链接或来源说明。

第一版素材数量建议控制在 50-100 个。质量优先于数量。

## 4. 素材元数据

每个素材需要有结构化元数据，至少包含：

- `id`：唯一标识。
- `name`：展示名称。
- `category`：分类，如 tape、paper、sticker、texture。
- `tags`：主题标签，如 coffee、travel、sunny、date、birthday。
- `style`：风格标签，如 soft-collage、hand-drawn、paper。
- `colors`：主色信息。
- `file`：素材文件路径。
- `license`：授权类型。
- `source`：来源，自绘素材标记为 internal。
- `qualityStatus`：质量状态，如 approved、draft、rejected。

只有 `approved` 素材可以参与 AI 自动选择。

## 5. 网站内素材预览页

第一版需要提供素材库预览页，用于人工掌控素材质量。

预览页能力：

- 按分类查看素材。
- 按标签筛选素材。
- 显示素材名称、分类、标签、授权和来源。
- 显示素材在浅色纸张背景上的实际效果。
- 区分 approved、draft、rejected 状态。
- 支持查看单个素材的大图预览。
- 对非 internal 来源素材显示来源和授权，避免后续忘记素材出处。

第一版不要求在页面内编辑素材元数据，也不要求上传素材。元数据可以先通过代码或配置文件维护。

## 6. AI 使用方式

AI 不直接决定具体素材文件路径，而是输出主题、情绪、颜色和标签。

后端根据 AI 输出的标签，从 approved 素材中匹配候选素材，再写入手帐结构化 JSON。

这样做的目的：

- 避免模型选择不存在的素材。
- 保证只使用通过质量审核的素材。
- 降低授权和风格失控风险。

## 7. 后续扩展

- 增加素材管理后台。
- 支持上传自定义素材。
- 支持 AI 生成素材后进入 draft 状态，人工审核通过后再使用。
- 支持按手帐主题自动生成素材包。
