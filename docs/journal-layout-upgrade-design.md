# 手帐版式升级设计方案

## 1. 背景

当前手帐生成已经具备图片理解、文字生成、素材选择、长图展示和 Agent Loop 复审能力，但版式仍偏固定。主要问题是：

- 图片主次关系不够明显，容易像普通图片列表。
- 正文虽然分段，但和图片组的绑定还不够强。
- 装饰元素有时像随机点缀，而不是参与手帐排版。
- 不同手帐之间结构相似，缺少“这一篇是专门为这组照片设计的”感觉。

本方案目标是把手帐从固定模板升级为“内容驱动的章节式长图拼贴”。AI 负责理解图片和规划故事结构，代码负责稳定排版和硬约束校验，Agent Loop 负责视觉复审和定向修订。

## 2. 设计目标

- 每篇手帐都根据图片数量、横竖比例、内容类型和用户描述选择不同版式。
- 手帐以一张可继续向下延伸的长图呈现，不限制固定高度。
- 图片、文字和装饰按章节组织，每章围绕 1-3 张相关图片展开。
- 文字像真实日记记录，简短、具体、和对应图片强绑定。
- 装饰元素必须有排版功能，禁止随机遮挡和无意义堆叠。
- 布局结果可通过规则校验和视觉 Agent Loop 稳定复审。

## 3. 核心概念

### 3.1 章节式长图

每篇手帐由多个章节组成：

- 顶部封面区：标题、日期、心情、少量主题装饰。
- 内容章节区：每章包含图片组、短文字、可选 caption 和功能性装饰。
- 收尾区：一句自然收尾、签名感小字或轻装饰。

章节数量由图片内容决定，一般为 2-5 个。图片较少时减少章节，图片较多时拉长画布，不压缩成密集网格。

### 3.2 版式族

系统不再只使用单一模板，而是维护一组可组合的版式族。AI 只选择版式族和参数，代码按版式族规则生成稳定坐标。

第一批版式族建议包含：

| 版式族 | 适用场景 | 特征 |
| --- | --- | --- |
| `hero_note` | 图片少或有明显主图 | 一张主图最大，文字便签贴在旁边 |
| `staggered_collage` | 多张生活照、约会、日常 | 图片错落旋转，留白区放文字 |
| `timeline_strip` | 一天记录、旅行、活动流程 | 按顺序纵向排列，章节之间有时间线或标签 |
| `photo_wall` | 图片多且内容相近 | 相册墙结构，主图和辅助图比例不同 |
| `magazine_whitespace` | 图片少、文字氛围强 | 大留白、轻装饰、杂志式呼吸感 |
| `ticket_memo` | 餐厅、咖啡、展览、出行 | 票据、标签、便签纸作为文字底板 |

### 3.3 视觉焦点

每个章节必须有一个视觉焦点：

- 主图尺寸通常是辅助图的 1.4-2 倍。
- 主图优先承载人物、食物、地点、事件核心画面。
- 辅助图用于补充氛围和细节。
- 文字块不能抢主图视觉中心。

### 3.4 功能性装饰

装饰按功能分类，而不是按素材随机选择：

- 胶带：固定照片或便签边缘。
- 便签纸：承载短文字。
- 票据/标签：承载日期、地点、章节标题或关键词。
- 小贴纸：放在角落、留白区或标题旁。
- 线条/箭头：引导视线。
- 花草星星：填补留白，不能遮挡主体。

AI 可以选择素材类别和情绪标签，最终位置由版式规则和安全区校验决定。

## 4. 生成流程

新版生成流程分为 7 步：

1. 图片理解
   AI 读取图片，输出每张图的内容摘要、主体位置、场景、情绪、横竖比例和适合分类。

2. 故事分组
   AI 按用户上传顺序，把图片分成 2-5 个章节。禁止随意打乱顺序，只允许把相邻图片合并为章节。

3. 文案生成
   每章生成 30-80 字自然日记。文字要具体，对应本章图片，不写空泛总结。

4. 版式选择
   AI 根据图片数量、比例和内容选择版式族。每章可以使用不同版式族，但整篇风格需要统一。

5. 布局生成
   后端根据版式族生成初始坐标，包括图片、文字块、底纸、胶带和贴纸。

6. 规则校验
   后端检查重叠、遮挡、间距、装饰密度、素材状态、画布高度和图片顺序。

7. Agent Loop 视觉复审
   渲染真实截图，由视觉模型检查图文匹配、主次关系、遮挡、留白和整体美观度。最多修订 3 轮，保存最高分版本。

## 5. 布局硬约束

以下规则由代码强制执行，不能只依赖 Prompt：

- 用户图片集合和顺序不可改变。
- 每篇最多 22 个装饰。
- 每个章节建议 3-6 个装饰，少图章节可更少。
- 每张图片至少 85% 可见。
- 文字块不能与图片重叠。
- 胶带只能贴近照片或便签边缘。
- 胶带最多覆盖图片边缘 12%。
- 贴纸不得遮挡人物脸、食物主体、宠物主体、文字区域。
- 图片之间最小间距 24px。
- 章节之间最小间距 80px。
- 文本块内文字必须完整可读，不能溢出容器。
- 素材必须是 `approved` 状态。
- 不允许在画布中显示素材文件名、内部编号或无意义英文。
- 画布高度根据内容自动增长。

## 6. 数据结构调整

建议在现有 layout JSON 上新增章节结构，保留向后兼容：

```json
{
  "canvas": {
    "width": 1080,
    "height": 2360,
    "background": "#fffaf1"
  },
  "content": {
    "title": "周末小记",
    "sections": [
      {
        "id": "section_1",
        "title": "窗边的下午",
        "imageIds": ["img_1", "img_2"],
        "body": "下午那会儿光线很好，我们坐在窗边慢慢吃东西。那杯饮料比想象中甜一点，但聊天很开心，所以也刚刚好。",
        "mood": ["warm", "daily"]
      }
    ]
  },
  "layout": {
    "variant": "staggered_collage",
    "sections": [
      {
        "sectionId": "section_1",
        "variant": "hero_note",
        "y": 220,
        "height": 620,
        "images": [],
        "texts": [],
        "decorations": []
      }
    ]
  }
}
```

旧字段 `content.body`、`layout.images`、`layout.texts`、`layout.decorations` 可以继续作为渲染扁平结果使用；新增 `sections` 用于生成、校验和复审。

## 7. Prompt 要求

初稿生成器需要输出：

- 图片理解结果。
- 章节划分。
- 每章短文字。
- 推荐版式族。
- 每章素材类别建议。

核心要求：

```text
你是电子手帐排版设计师。图片顺序是用户确认后的叙事顺序，禁止重排。
请先把相邻图片按内容分成 2-5 个章节，再为每章写 30-80 字自然日记。
文字要像真实生活记录，不要像 AI 总结。
每章必须和本章 imageIds 的真实可见内容对应。
装饰只能选择功能类别：tape、note、ticket、label、sticker、line、flower、star。
输出严格 JSON。
```

视觉评审器需要重点检查：

- 是否有明确主图。
- 图片与文字是否对应。
- 装饰是否有功能。
- 胶带是否贴在边缘。
- 是否存在遮挡。
- 是否有足够留白。
- 整体是否像电子手账，而不是普通图文列表。

## 8. 渲染策略

前端渲染仍使用 `JournalCanvas`，但渲染输入改为章节式 layout：

- 先渲染背景纸纹理。
- 按章节从上到下渲染。
- 每章内部按层级渲染：底纸、图片、胶带、文字、贴纸、线条。
- 每章渲染完成后根据实际高度决定下一章 y 坐标。
- 移动端继续按画布宽度缩放，保持长图上下滚动。

## 9. 验收标准

- 同样的图片数量不总是生成同一种结构。
- 图片多时画布自然变长，不挤成固定高度。
- 每章文字能明确对应本章图片。
- 每篇至少有一个清晰视觉焦点。
- 胶带贴近照片或便签边缘。
- 贴纸和装饰不遮挡主体。
- 文字不和图片重叠。
- 历史手帐仍能正常打开。
- PNG 导出仍和预览一致。
