# AI 日记手帐应用需求文档

## 1. 产品概述

本项目第一版是一个 Web 单页应用。用户登录后，可以上传一组生活图片，输入一段简短描述，并可选填写日期、地点、心情标签。系统通过 AI 自动生成一篇温柔拼贴风格的精美手帐，内容由 AI 生成文字、用户上传图片、主题装饰元素和结构化版式组成。

第一版重点验证“低输入成本生成高质量手帐”的核心体验，不做复杂设计工具、付费体系或多端客户端。

## 2. 目标用户与场景

目标用户是希望记录生活但不想手动排版的人，包括日常记录、旅行记录、聚会记录、节日记录等场景。

典型使用流程：

1. 用户登录应用。
2. 上传 1-9 张图片。
3. 输入一段自由文本描述，并可选填写日期、地点、心情标签。
4. 点击生成。
5. 系统生成一篇手帐草稿。
6. 用户进行轻量编辑。
7. 保存到云端历史记录。
8. 导出 PNG 图片。

## 3. 第一版核心功能

### 3.1 账号与云端保存

- 用户需要登录后使用应用。
- 用户生成的手帐需要保存到云端。
- 用户可以查看自己的历史手帐列表。
- 用户可以打开历史手帐继续查看、轻量编辑和再次导出。
- 第一版采用账号密码登录。
- 第一版不要求公开分享链接。
- 第一版不要求多人协作。

### 3.2 图片上传

- 支持一次上传 1-9 张图片。
- 支持常见图片格式，如 JPG、PNG、WebP。
- 上传后需要展示缩略图预览。
- 用户可以删除已上传图片。
- 系统长期保存原图。
- 系统需要为上传图片生成缩略图。
- 删除手帐时，需要删除该手帐关联的图片文件和缩略图。
- 第一版不要求图片裁剪、滤镜、手动排序或高级编辑。

### 3.3 文本输入

用户输入由两部分组成：

- 必填：一段自由文本描述。
- 可选：日期、地点、心情标签。

自由文本示例：

> 今天和朋友去了海边，天气很好，拍了很多照片，傍晚一起吃了烧烤。

这些输入会用于生成手帐标题、正文、图片说明、主题关键词、装饰元素和整体情绪。AI 必须理解用户上传图片的实际内容，而不是只根据文件名、图片 ID、尺寸或用户描述进行推测。

### 3.4 AI 生成手帐

系统基于用户输入和图片内容生成结构化手帐数据，而不是直接生成一张不可编辑图片。

AI 生成必须使用多模态图片理解能力。模型需要根据上传图片识别场景、人物或主体、物品、天气、时间感、色彩、氛围和可能的事件，再结合用户描述生成手帐内容和排版。图片说明、正文情绪、主题关键词和素材选择应能反映图片中的真实内容。

AI 生成内容包括：

- 手帐标题。
- 分段正文。
- 图片使用建议。
- 图片说明或短句。
- 版式结构。
- 配色建议。
- 装饰元素建议。
- 整体主题关键词。

生成结果需要使用结构化 JSON 表达，前端根据 JSON 渲染成手帐画布。

第一版需要真实调用 OpenAI API 生成内容，暂不做额度系统。

### 3.5 视觉风格

第一版默认视觉方向为“温柔拼贴”。

全站固定使用以下主配色方案：

- `#ffcdb2`：浅桃色，用于页面底色、柔和背景和大面积暖色氛围。
- `#ffb4a2`：蜜桃色，用于面板渐变、弱强调和浅色边框。
- `#e5989b`：玫瑰色，用于提示、状态和局部强调。
- `#b5838d`：豆沙紫，用于品牌强调、链接、焦点态和次级按钮。
- `#6d6875`：灰紫色，用于主要文字、主按钮、导航激活态和高对比内容。

界面文字必须在该配色下保持清晰可读，不能出现浅色文字叠在浅色背景上导致表单内容不可见的情况。

视觉特征：

- 纸张、胶带、贴纸、照片叠放感。
- 温暖、柔和、生活化。
- 适合日常、旅行、聚会、节日等生活记录。
- 图片应像真实手帐中的照片一样参与排版，而不是只作为普通图库。
- 装饰元素应服务主题，避免喧宾夺主。

第一版可以只提供少量固定模板或布局变体，但生成结果需要看起来像经过设计，而不是简单图文列表。

### 3.6 装饰元素

装饰元素第一阶段采用内置素材库。代码结构需要预留少量定制生成能力，但定制小元素生成不作为第一阶段硬依赖。

- 从内置素材库中按主题选择贴纸、胶带、纸张、手绘小元素等。
- 素材库需要免费、授权清晰、风格统一。
- 素材质量优先于数量，第一版建议控制在 50-100 个高质量素材。
- 只有通过质量审核的素材可以参与自动生成。
- 小元素需要和手帐主题、情绪、配色一致。
- 网站需要提供素材库预览页，用于人工查看素材质量、分类、标签、授权和来源。
- 第一版不要求用户在页面内上传或编辑素材。

### 3.7 轻量编辑

生成后用户可以进行轻量编辑，但第一版不做完整设计工具。

必须支持：

- 修改 AI 生成的标题和正文。
- 更换模板或布局变体。
- 重新生成文案。
- 重新生成或替换装饰元素。
- 保存编辑后的结果。

不要求支持：

- 任意拖拽元素。
- 自由缩放、旋转、图层管理。
- 高级字体排版工具。
- 类似 Figma 或 Canva 的完整编辑体验。

### 3.8 PNG 导出

- 用户可以将最终手帐导出为 PNG 图片。
- 第一版固定导出尺寸为 1080 x 1440。
- 导出结果应与预览画布保持一致。
- 第一版只要求 PNG 导出。
- 第一版不要求 PDF 导出。
- 第一版不要求公开分享链接。

## 4. 核心数据形态

第一版内部应以结构化数据作为手帐的真实来源。前端渲染、编辑、保存和导出都围绕该数据进行。

手帐数据应至少包含：

- 基本信息：标题、创建时间、更新时间、用户 ID。
- 用户输入：原始描述、日期、地点、心情标签。
- 图片列表：图片 URL、缩略图 URL、顺序或使用建议。
- AI 文案：标题、正文段落、图片说明。
- 视觉主题：风格、配色、字体建议。
- 布局信息：画布尺寸、区域、图片位置、文本位置、装饰元素位置。
- 装饰元素：素材 ID、类型、位置、尺寸、旋转角度。

结构化数据需要能被保存、再次加载、轻量编辑和重新导出。

## 5. 页面与流程需求

### 5.1 登录页

- 用户可以登录应用。
- 第一版采用账号密码登录。

### 5.2 创建页

- 上传图片。
- 输入自由文本描述。
- 可选填写日期、地点、心情标签。
- 发起生成。
- 展示生成中状态。

### 5.3 预览与编辑页

- 展示生成后的手帐画布。
- 支持轻量编辑。
- 支持保存。
- 支持重新生成文案或装饰元素。
- 支持导出 PNG。

### 5.4 历史页

- 展示当前用户保存过的手帐。
- 支持打开历史手帐。
- 支持按更新时间或创建时间排序。

### 5.5 素材库预览页

- 展示内置素材库。
- 支持按分类和标签筛选。
- 展示素材名称、分类、标签、授权和来源。
- 展示素材在手帐纸张背景上的实际效果。
- 区分 approved、draft、rejected 状态。
- 第一版不要求在页面内编辑素材元数据。

## 6. 状态与异常

需要覆盖以下状态：

- 未登录。
- 图片未上传。
- 描述为空。
- 图片数量超过限制。
- 上传中。
- 生成中。
- 生成失败。
- 保存失败。
- 导出失败。

错误提示需要明确告诉用户发生了什么，以及下一步可以怎么做。

## 7. 非目标

第一版不包含以下能力：

- 移动端原生应用。
- PWA 离线能力。
- 复杂设计工具。
- PDF 导出。
- 公开分享链接。
- 支付、订阅、积分或额度系统。
- 多人协作。
- 社区发布和公开作品广场。
- 无限图片上传。

## 8. 验收标准

第一版完成后，应满足以下标准：

- 用户可以登录并进入应用。
- 用户可以上传 1-9 张图片。
- 用户可以输入自由文本，并可选填写日期、地点、心情标签。
- 系统可以生成一篇温柔拼贴风格手帐。
- AI 生成结果能体现上传图片中的真实场景、主体、颜色和氛围。
- 生成结果由结构化数据驱动渲染。
- 系统只使用 approved 状态的内置素材参与自动生成。
- 用户可以在素材库预览页查看素材质量、标签、授权和来源。
- 用户可以修改标题和正文。
- 用户可以更换布局变体。
- 用户可以重新生成文案或装饰元素。
- 用户可以保存手帐到云端。
- 用户可以在历史列表中找到并打开已保存手帐。
- 用户可以导出 PNG。
- 导出的 PNG 与预览效果一致。

## 9. 后续可扩展方向

以下能力不属于第一版，但数据结构和架构设计应尽量避免阻碍后续扩展：

- 多种手帐风格模板。
- 更强的拖拽编辑能力。
- PDF 导出。
- 分享链接和公开展示页。
- 用户素材库。
- 付费额度或订阅。
- 移动端适配和 PWA。
- 社区作品广场。
